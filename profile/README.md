# EF Commander — dual pane folders with archive view

EF Commander keeps one named board on the desk: the live dual panes, the archive in front of you, and a short note the next person can read. Extra folder pairs wait for their own title.

## Session Card

| Slice | What you do in EF Commander | What remains |
|-------|------------------------|--------------|
| Arrival | Open EF Commander and name today's file desk | A titled folder pair |
| Focus | Keep only live panes on the EF Commander board | A short tab list |
| Check | Read EF Commander archive view before a large pane change | A confirmed file desk |
| Handoff | Mark finished tabs inside EF Commander | A note for the next person |

## How EF Commander Sits

EF Commander does not replace Explorer, the unlabeled archive pile, or a second window on folders you do not own. It sits beside them as a named file desk for one job: which dual pane is live, which file tabs still match the archive view, and what the next person should read on two folders you own.

Each person on a shared PC keeps an EF Commander style of their own. Extra folder pairs wait for their own title instead of crowding the live panes.

A first visit should be one short dual-pane pass on two folders you own, then the same EF Commander file desk the next day. That is enough to see if the named tabs hold.

## Traffic Light

| Signal | On the EF Commander board | What you do |
|--------|----------------------|-------------|
| Green | Named folder pair, short live pane list | Continue the same dual pane |
| Amber | Two jobs mixed across the panes | Split the tabs before a large change |
| Red | No title, no note, panes on folders you do not own | Stop and name the file desk first |
| Clear | Handoff written, live tabs few | Close EF Commander and leave the file desk |

## Open Order

1. Open the last EF Commander file desk, not a new empty folder pair.
2. Read the archive view and the last handoff.
3. Finish one visible dual-pane pass inside EF Commander on folders you own.
4. Write what changed, then close with fewer unlabeled archives than you found, and keep the panes on two folders you own.

## After a Week

A week in EF Commander is not a larger unlabeled archive pile. It is the same title, a shorter live pane list, and a note that still makes sense before the next pair of folders you own. Take finished tabs off the live set so the next visit starts on the file desk that is still open.

Other programs stay where they are. EF Commander only keeps the path back: desk name, dual pane, archive view, handoff.

## Sign-off

- [ ] The EF Commander workspace name is short enough to scan
- [ ] Only live panes sit on folders you own
- [ ] A second person can read the archive handoff
- [ ] The last EF Commander folder pair still opens after a restart
- [ ] Finished tabs are off the live EF Commander set
- [ ] The EF Commander summary still matches the archive view on the board

## Field Note

EF Commander is easier to trust when the file desk stays smaller than the unlabeled archive pile it came from. Name the folder pair, keep the live panes, finish one visible archive view, and write what changed.

The same loop fits a home pair, shop files, or a shared PC. Open the last EF Commander desk and continue. Do not rebuild the commander pair from folders you do not own.
